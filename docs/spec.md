## 1. 개요

- 목적: 데모 범위에서 만들 화면, 기능, 정책을 정의함. 현재 구현 상태는 [implementation.md](implementation.md)에 기록함.
- 타깃: IT 관련 분야 학부생과 대학원생.
- 로그인 없음. 관심 분야, 읽기 수준, 저장 목록, 출석 기록은 브라우저에만 저장함.
- 기준 문서 우선순위: 프론트엔드 작업 지시서(2026-11-07) → `docs/design/` → 백엔드 문서 → 노션 개발문서(화면 흐름만).

## 2. 화면

| 경로                    | 화면             | 내용                                                                 |
| ----------------------- | ---------------- | -------------------------------------------------------------------- |
| `/`                     | 시작             | 마스코트, 소개 한 줄, "시작하기", 약관 안내. 프로필이 있으면 `/home` |
| `/onboarding/interests` | 관심 분야 선택   | 5개 분야 키워드 칩, 최소 3개                                         |
| `/onboarding/swipe`     | 카드 10장 평가   | 좌 = 별로, 우 = 흥미로워요, 건너뛰기, 되돌리기 1회                   |
| `/onboarding/done`      | 취향 분석 완료   | 상위 관심 키워드 1~3위, 기본 읽기 수준 선택                          |
| `/home`                 | 홈 (탭)          | 헤더 → 출석 스트릭 → 대체 안내 → 오늘의 논문 → 나를 위한 추천        |
| `/feed`                 | 피드 (탭)        | 논문 하나당 한 화면, 세로 스냅, 우측 레일(저장 · 공유)               |
| `/papers/:paperId`      | 논문 상세        | 읽기 수준 선택, 요약 섹션, 원문 보기, 출석 인정                      |
| `/saves`                | 저장함 (탭)      | 전체 · 최근 저장(7일) 필터                                           |
| `/menu`                 | 메뉴 (탭)        | 스트릭 요약, 관심 키워드, 설정, 이용약관, 개인정보 안내, 문의        |
| `/menu/keywords`        | 관심 키워드 관리 | 분야 키워드 다시 선택                                                |
| `/menu/settings`        | 설정             | 기본 읽기 수준, 기기 데이터 초기화                                   |
| `/terms`                | 이용약관         | 작업 지시서 부록 A 본문, 시행일 2026-11-08                           |
| `/demo`                 | 시연 도구        | `VITE_DEMO_TOOLS=true`일 때만. "12일째로 설정", 초기화               |
| `*`                     | 404              |                                                                      |

- 하단 탭은 홈 · 피드 · 저장함 · 메뉴 4개. 프로필 없이 탭 화면에 들어오면 `/onboarding/interests`로 보냄.
- 온보딩 관심 분야: 인공지능(`cs.AI`), 자연어처리(`cs.CL`), 컴퓨터 비전(`cs.CV`), HCI(`cs.HC`), 소프트웨어공학(`cs.SE`). 키워드 슬러그는 고정 목록임 `[BE 협의]`.
- 상세 섹션 순서: 한 줄 요약(형광펜) → 왜 중요한가 → 핵심 포인트 → 방법 · 데이터 · 한계(접기) → 논문 정보 → 원문 보기.
- 메뉴의 기기 데이터 초기화는 확인 시트를 거친 뒤 `nonstop:v1:` 키를 모두 지우고 `/`로 이동함.

## 3. 제스처

| 위치   | 제스처                                                  | 대체 수단                 |
| ------ | ------------------------------------------------------- | ------------------------- |
| 피드   | 위 · 아래 스와이프로 이전 · 다음 논문                   | 위 · 아래 방향키          |
| 피드   | 오른쪽 스와이프로 상세 (왼쪽 가장자리 20px 시작은 무시) | 카드 탭, 오른쪽 방향키    |
| 온보딩 | 좌 · 우 드래그로 별로 · 흥미로워요                      | 하단 버튼, 좌 · 우 방향키 |

- 두 번 누르기, 길게 누르기, 피드 안 가로 카드 넘김은 쓰지 않음.

## 4. 기기 저장과 출석 스트릭

| localStorage 키      | 내용                                                   |
| -------------------- | ------------------------------------------------------ |
| `nonstop:v1:profile` | 관심 키워드와 가중치, 기본 읽기 수준, 온보딩 완료 시각 |
| `nonstop:v1:saves`   | `{ paperId, savedAt }` 배열                            |
| `nonstop:v1:streak`  | 현재 · 최장 일수, 마지막 인정일, 최근 7일 날짜         |
| `nonstop:v1:read`    | 최근 읽은 `paperId` 최대 50개 (홈 추천 제외용)         |

- 저장소 읽기 · 쓰기는 실패할 수 있다고 보고 처리함. 비어 있으면 처음 방문으로 봄.
- 출석은 한국 날짜 기준 그날 상세를 한 번 이상 열면 인정함. 날짜는 홈 응답의 `today`를 씀.
- 판정: 같은 날이면 변경 없음, 전날이면 `+1`, 그 외는 `1`로 다시 시작. 최장 기록 갱신, 최근 7일 유지. 날짜는 UTC 문자열로 계산함.
- 7일 · 30일 도달 시 마스코트 축하와 토스트를 보여 줌. 보호 장치와 레벨은 없음.

## 5. API

| 메서드 | 경로                   | 사용처         |
| ------ | ---------------------- | -------------- |
| GET    | /v1/onboarding/cards   | 카드 평가 10장 |
| POST   | /v1/onboarding/weights | 온보딩 완료    |
| GET    | /v1/home               | 홈, `today`    |
| GET    | /v1/feed               | 피드 (커서)    |
| GET    | /v1/papers/{paperId}   | 상세 (`level`) |
| GET    | /v1/papers             | 저장함 (`ids`) |

- 인증 헤더 없음. 오류는 RFC 9457 Problem Details와 `code` 필드.
- `paperId`는 버전 없는 arXiv ID(구형 ID의 `/`는 `_`). `status`는 `ready` · `hidden`이며 `hidden`은 거름.
- 첫 요청 제한 시간 70초, 3초가 지나면 "서버를 깨우는 중이에요. 잠시만 기다려 주세요" 표시.
- MSW 목을 기본으로 쓰고 `VITE_API_MOCK=false`일 때만 실제 API를 씀.

## 6. 공통 상태와 비기능 요구사항

| 항목      | 기준                                                                 |
| --------- | -------------------------------------------------------------------- |
| 로딩      | 최종 레이아웃 모양의 스켈레톤. 스피너 · 햄스터 로더 없음             |
| 빈 화면   | 마스코트, 채우는 방법 한 문장, 행동 버튼 하나                        |
| 오류      | 원인과 "다시 시도" 버튼                                              |
| 화면 크기 | 기준 375px, 최소 360px, 데스크톱은 가운데 480px. 높이는 `h-dvh`      |
| 접근성    | 텍스트 대비 4.5:1, 그래픽 3:1, 포커스 링 유지, 모든 조작 키보드 가능 |
| 테마      | 라이트 모드만                                                        |
| 움직임    | `prefers-reduced-motion`에서 즉시 전환                               |
| 개인정보  | 서버에는 관심 키워드와 제외할 논문 ID만 요청 파라미터로 보냄         |

## 7. 구현 정책

- 서버 데이터는 TanStack Query, 기기 데이터는 Zustand `persist`로만 관리함.
- 색 · 글자 · 모양은 디자인 토큰 유틸리티로만 씀. 16진 색, 대괄호 임의 값, 그라데이션, 블러, 장식 그림자, inline style은 린트로 막음.
- AI 생성 카드에는 항상 "AI 요약" 배지를 붙이고, 한국어 제목 아래 영어 원제를 표기함.
- 원문은 arXiv 초록 페이지를 새 탭으로 열기만 함.
- 테스트 대상: 출석 판정, 기기 저장, 온보딩 3개 미만 검증, 읽기 수준 방향키 조작, API 오류 파싱.
