# 논스톱 프론트엔드 명세

화면 명세, 기능 명세, 비기능 요구사항, 구현 정책, 일정을 담는다. 백엔드 [docs/spec.md](https://github.com/nonstop-2026/nonstop-be/blob/main/docs/spec.md)와 짝을 이루며, 기능 ID(FR-xx-xx)는 백엔드와 같은 번호를 쓴다. 결정 배경은 [CLAUDE.md](../CLAUDE.md)와 [계획서](plan/frontend-plan.html)에 있다.

- **API 계약의 기준은 백엔드 `openapi.yaml`이다.** 아직 없어서 응답 타입은 [src/shared/api/types.ts](../src/shared/api/types.ts)에 임시로 적었고, 명세가 나오면 `pnpm gen:api`로 생성한 타입으로 바꾼다.
- 백엔드 오픈 이슈에 걸린 항목은 "⏳ BE #번호"로 표시한다. 정해지기 전까지 MSW 목으로 진행한다.

## 화면별 동작

### 피드 (`/feed`)

- 세로 스와이프 = 다음 논문, 가로 스와이프 = 같은 논문의 다음 카드.
- 가로 카드 순서: 한 줄 요약 → 왜 중요한가 → 핵심 포인트 → 방법 · 데이터 → 한계 → (있으면) 편집팀 해설.
- 카드 아래 점 표시로 현재 카드 위치를 보여준다.
- 키보드: ↑↓ 논문 이동, ←→ 카드 이동.
- 읽기 수준을 바꾸면 해당 논문만 그 수준으로 다시 받는다. 피드 전체의 기본값은 바꾸지 않는다.
- 좋아요 · 저장은 낙관적 업데이트로 즉시 반영하고, 실패하면 되돌린 뒤 토스트로 알린다.

### 홈 (`/home`)

- 순서: 상태 배너(있을 때) → 오늘의 대표 논문 → 키워드 칩 → 나를 위한 추천.
- 상태 배너: `isDelayed`면 "오늘 논문을 준비하는 데 시간이 걸리고 있어요", `isFallback`이면 "최근 3일 논문을 모았어요".

### 상세 (`/papers/:paperId`)

- 피드와 같은 카드 구성 + 논문 정보(제목, 저자, 게시일, 카테고리, 라이선스).
- "원문 보기"는 arXiv 초록 페이지를 새 탭으로 연다. PDF를 띄우거나 내려받지 않는다.

### 온보딩

- 가입 동의 → 관심 분야 → 카드 평가 → 초기 설정 → 홈. 중간에 나가면 다음 로그인 때 남은 단계부터 이어서 한다.
- iOS Safari에서 알림을 켜려 하면 "공유 → 홈 화면에 추가" 안내를 먼저 보여준다(iOS는 홈 화면에 추가한 웹앱만 푸시를 받는다).

### 마이 (`/me`)

- 기본 읽기 수준, 알림 켜기 · 시간, 관심 키워드 관리, 로그아웃, 탈퇴.
- 탈퇴는 2단계 확인(안내 → 확인 입력)을 거친다. 서버 처리 방식은 ⏳ BE #15.

## 구현 정책

### FP-01 API와 목 서버

- 모든 요청은 `apiFetch`([src/shared/api/client.ts](../src/shared/api/client.ts))를 거친다. ID Token을 `Authorization: Bearer`로 붙이고, 401이면 토큰을 새로 받아 한 번 더 시도한다.
- MSW 목은 마감 이후에도 유지한다. `VITE_API_MOCK=false`일 때만 실제 API를 쓴다. 발표 시연이 백엔드 상태에 묶이지 않게 하기 위해서다.
- 목 핸들러 경로는 백엔드 엔드포인트 표를 그대로 따른다.

### FP-02 상태 관리

- 서버 데이터는 TanStack Query로만 다룬다. 같은 데이터를 컴포넌트 상태에 복사하지 않는다.
- Zustand는 기기에 남길 화면 설정(기본 읽기 수준 등)과 전역 UI 상태에만 쓴다.
- 쿼리 키는 기능 폴더의 `api.ts`에 모아 둔다(예: `homeKeys`).

### FP-03 디자인 토큰

- 색 · 글꼴 · 그림자 · 앱 폭은 [src/app/styles/index.css](../src/app/styles/index.css)의 `@theme` 토큰으로만 쓴다. 16진 색을 컴포넌트에 직접 쓰지 않는다.
- 카테고리 색은 `cat-*` 토큰과 [categories.ts](../src/shared/constants/categories.ts)의 매핑으로 관리한다.

### FP-04 콘텐츠 표기

- AI 생성 카드에는 "AI 요약" 배지를, 편집팀 해설에는 다른 색의 "편집팀 해설" 배지를 붙인다.
- 원문은 링크로만 연다. 논문 원문 · 초록 전문을 화면에 옮겨 적지 않는다.

### FP-05 PWA · 푸시

- 서비스 워커는 배포 빌드 + 실제 API 모드에서만 등록한다. 목 모드에서는 MSW 워커와 범위가 겹치기 때문이다.
- FCM 메시징은 PWA 서비스 워커 등록을 함께 쓴다. 권한 요청은 사용자가 알림을 켜는 순간에만 한다(첫 화면에서 바로 묻지 않음).

### FP-06 코드 구조

```
src/
├─ app/        라우터, 레이아웃(AppShell, TabLayout), 전역 스타일, 서비스 워커 등록
├─ features/   화면 단위 기능(auth, onboarding, home, feed, paper, saves, me, push)
├─ shared/     api · config · constants · lib · store · ui (여러 기능이 같이 쓰는 것)
├─ mocks/      MSW 핸들러와 목 데이터
└─ test/       Vitest 설정
```

- 기능 폴더끼리는 서로 import하지 않는다. 같이 써야 하면 `shared/`로 옮긴다.

### FP-07 품질

- PR마다 CI가 포맷 · 린트 · 타입 · 테스트 · 빌드를 검사한다.
- 테스트는 핵심 로직 위주: API 클라이언트, 온보딩 검증(3개 이상), 피드 페이지네이션, 공통 컴포넌트.
