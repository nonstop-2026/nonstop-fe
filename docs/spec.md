## 1. 개요

### 1.1 목적

논스톱 프론트엔드의 화면, 기능, 비기능 요구사항, 구현 정책, 일정을 정의함.

### 1.2 기준

- 기능 ID(FR-xx-xx)와 우선순위는 백엔드 명세와 동일한 번호 · 기준을 사용함.
- API 계약의 기준은 백엔드 `openapi.yaml`임. 현재 미작성 상태이므로 응답 타입은 [src/shared/api/types.ts](../src/shared/api/types.ts)에 임시 정의함. 명세 확정 후 `pnpm gen:api`로 생성한 타입으로 교체함.
- 결정 배경은 [CLAUDE.md](../CLAUDE.md)와 [계획서](plan/frontend-plan.html) 참조.

### 1.3 표기 규칙

| 표기                | 의미                                                            |
| ------------------- | --------------------------------------------------------------- |
| `[BE #n]`           | 백엔드 오픈 이슈 n번에 걸린 항목. 확정 전까지 MSW 목으로 진행함 |
| 로그인 `-`          | 누구나 접근 가능                                                |
| 로그인 `둘러보기`   | 비로그인 상태에서도 열람 가능                                   |

| 로그인 `필요`       | 로그인 + 가입 완료 필요                                         |
| 순위 `P0 · P1 · P2` | MVP 필수 · 중요 · 후순위                                        |
| 11/18 `포함`        | 11/18 마감 범위에 포함                                          |
| 11/18 `일부`        | 일부 기능만 마감 범위에 포함                                    |

## 4. 화면별 동작

### 4.1 피드 (SCR-07)

- 세로 스와이프: 다음 논문. 가로 스와이프: 같은 논문의 다음 카드.
- 가로 카드 순서: 한 줄 요약 → 왜 중요한가 → 핵심 포인트 → 방법 · 데이터 → 한계 → 편집팀 해설(있을 때만).
- 카드 하단 점 표시로 현재 카드 위치 표시.
- 키보드 조작: 위 · 아래 방향키로 논문 이동, 좌 · 우 방향키로 카드 이동.
- 읽기 수준 변경 시 해당 논문만 그 수준으로 재요청. 피드 전체 기본값은 변경하지 않음.
- 좋아요 · 저장은 낙관적 업데이트로 즉시 반영. 실패 시 원상 복구 후 토스트로 안내.

### 4.2 홈 (SCR-06)

- 구성 순서: 상태 배너(있을 때만) → 오늘의 대표 논문 → 키워드 칩 → 나를 위한 추천.
- 상태 배너 문구:

| 조건         | 화면 문구                                      |
| ------------ | ---------------------------------------------- |
| `isDelayed`  | "오늘 논문을 준비하는 데 시간이 걸리고 있어요" |
| `isFallback` | "최근 3일 논문을 모았어요"                     |

### 4.3 상세 (SCR-08)

- 카드 구성은 피드와 동일. 논문 정보(제목, 저자, 게시일, 카테고리, 라이선스)를 추가 표시.
- "원문 보기"는 arXiv 초록 페이지를 새 탭으로 열기만 함. PDF 표시 · 다운로드 금지.

### 4.4 온보딩 (SCR-02 ~ SCR-05)

- 진행 순서: 가입 동의 → 관심 분야 → 카드 평가 → 초기 설정 → 홈.
- 중도 이탈 시 다음 로그인 때 미완료 단계부터 재개.
- iOS Safari에서 알림 켜기 시도 시 "공유 → 홈 화면에 추가" 안내를 먼저 표시함. iOS는 홈 화면에 추가한 웹앱만 푸시 수신 가능.

### 4.5 마이 (SCR-10)

- 설정 항목: 기본 읽기 수준, 알림 켜기 · 시간, 관심 키워드 관리, 로그아웃, 탈퇴.
- 탈퇴는 2단계 확인(안내 → 확인 입력) 필수. 서버 처리 방식은 `[BE #15]`.

## 7. 구현 정책

### FP-01 API와 목 서버

- 모든 요청은 `apiFetch`([src/shared/api/client.ts](../src/shared/api/client.ts))를 거침. ID Token을 `Authorization: Bearer`로 첨부하고, 401이면 토큰 재발급 후 1회 재시도.
- MSW 목은 마감 이후에도 유지. `VITE_API_MOCK=false`일 때만 실제 API 사용. 발표 시연이 백엔드 상태에 의존하지 않도록 하기 위함.
- 목 핸들러 경로는 백엔드 엔드포인트 표를 그대로 따름.

### FP-02 상태 관리

- 서버 데이터는 TanStack Query로만 관리. 같은 데이터를 컴포넌트 상태에 복사하지 않음.
- Zustand는 기기에 남길 화면 설정(기본 읽기 수준 등)과 전역 UI 상태에만 사용.
- 쿼리 키는 기능 폴더의 `api.ts`에 모아 관리(예: `homeKeys`).

### FP-03 디자인 토큰

- 색 · 글꼴 · 그림자 · 앱 폭은 [src/app/styles/index.css](../src/app/styles/index.css)의 `@theme` 토큰으로만 사용. 컴포넌트에 16진 색 직접 사용 금지.
- 카테고리 색은 `cat-*` 토큰과 [categories.ts](../src/shared/constants/categories.ts)의 매핑으로 관리.

### FP-04 콘텐츠 표기

- AI 생성 카드에는 "AI 요약" 배지, 편집팀 해설에는 다른 색의 "편집팀 해설" 배지를 부착.
- 원문은 링크로만 엶. 논문 원문 · 초록 전문을 화면에 옮겨 적지 않음.

### FP-05 PWA · 푸시

- 서비스 워커는 배포 빌드 + 실제 API 모드에서만 등록. 목 모드에서는 MSW 워커와 범위가 겹치기 때문.
- FCM 메시징은 PWA 서비스 워커 등록을 공유함. 권한 요청은 사용자가 알림을 켜는 시점에만 수행(첫 화면에서 바로 요청하지 않음).

### FP-06 코드 구조

```
src/
├─ app/        라우터, 레이아웃(AppShell, TabLayout), 전역 스타일, 서비스 워커 등록
├─ features/   화면 단위 기능(auth, onboarding, home, feed, paper, saves, me, push)
├─ shared/     api · config · constants · lib · store · ui (여러 기능이 같이 쓰는 것)
├─ mocks/      MSW 핸들러와 목 데이터
└─ test/       Vitest 설정
```

- 기능 폴더 간 상호 import 금지. 공용이 필요하면 `shared/`로 이동.

### FP-07 품질

- PR마다 CI가 포맷 · 린트 · 타입 · 테스트 · 빌드를 검사함.
- 테스트 대상은 핵심 로직 위주: API 클라이언트, 온보딩 검증(3개 이상), 피드 페이지네이션, 공통 컴포넌트.
